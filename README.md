# 直播带货口播与上架窗口取证的演练来源

这里提供独立来源的本地合成记录，与实际单位、个人和线上业务无关。

## 本地运行

使用 Node.js 22.23.4。只使用 Node.js 自带的运行库。

执行 `npm test` 检查合成来源的接口。执行 `npm start` 启动来源，默认监听 `127.0.0.1:4100`，可通过环境变量 `PORT` 调整端口。访问根路径可看到来源名和当前回放阶段。

## 接口资料

| GET 路由 | 来源约定 |
| --- | --- |
| `/source/replay` | 媒体时码以毫秒表示。offset 把 local 会话时间换算到 broadcast 的时间。无映射表示暂未确认关联。 |
| `/source/control` | 窗口为 broadcast 毫秒，商品卡关系由 card 指定。revision 只更新同 card。 |
| `/source/listings` | 商品使用商户与 SKU 合并识别。valid 是口播当时的播出时码范围，撤回后历史档仍按明示时段可查。 |

查询参数 `offset` 是从零开始的页偏移，`limit` 默认 3，取值 1 至 100。响应中的 `records` 含 `record` 来源记录键、`availableFrom` 首次出现的回放阶段、`kind` 记录类型、`payload` 业务字段。来源记录键与业务身份分别定义。`next` 为下一页偏移，末页为 `null`。回放阶段中的记录按到达顺序可查。

控制员通过 `POST /control?stage=2` 切换到第 2 阶段，服务会保留更早已可查的记录。每次换阶段后按根路径返回的 `stage` 确认切换成功。原件通过 `GET /original/文件名` 领取，阶段内尚不可领时返回 404。原件文件和摘要记录在 `originals/` 与来源索引。

回放为两个真实编码的 13 秒 WebM 片段。画面只含合成校验图案。供审阅的口播内容由回放源的转写记录提供，重连后片段时码重新从 0 开始。

## 取证客户端

在来源服务之上提供口播承诺取证工具，同样只使用 Node.js 自带运行库：

- `src/source-client.mjs`：分页领取客户端。按 `next` 游标分段领取回放索引与转写修订、场控商品卡交接、商品资料版本档，并领取原件计算 SHA-256 摘要作片段凭据。
- `src/evidence-store.mjs`：证据核心。职责：
  - 时轴：每场首个会话为基准会话（local 即 broadcast）；重连会话时码从零重计，只有平台 clock 映射能拼回时轴；重新开播形成独立会话，各场互不混用。
  - 归属：字幕自带商户与 SKU 为明确归属；否则按口播播出区间与商品卡窗口的重叠收集候选，商品卡允许重叠，边界不清时保留全部候选；商品卡撤下后继续口播的区间记为无卡覆盖空档，不强行归属。
  - 承诺：同一 continuation 的片段可跨重连点组装；全部片段都能按原时码纽带证明且商品已确定才算完整承诺，否则标记已确定商品与缺失区间，不进入可提交清单。
  - 检查项：检查员录入关注的口播区间，同一段视频可被多个检查项引用，单个检查结束只释放自己的租约。
  - 提交与回查：提交时冻结片段凭据与归属快照；场控补发切卡时点或转写修订到达后，回查已提交证据并标明哪些归属受影响。
  - 版本：商户公告成分按口播当时的播出时码绑定版本档；后续领到的现价版本不改写已提交解释，只在其适用区间与口播区间相交时标出争议。
  - 凭据：内容撤回后，已提交片段凭据在保留期内可查；尚未归属或未收全的片段不进入可提交清单与凭据清单。
  - 追查：`traceProduct` 从商品正向追查版本、商品卡、口播、承诺、检查项与争议；`traceInterval` 从口播区间反向追查落位依据、涉及字幕与商品卡、归属候选与争议，均带来源记录键与版本。
- `src/cli.mjs`：走查演示。先 `npm start` 启动来源，再 `npm run audit`，按 4 个回放阶段分段领取、组装承诺、提交证据并回查争议。

`npm test` 同时检查来源接口与取证流程（含跨重连承诺、重叠卡候选、补发切卡回查、版本绑定与保留期凭据）。
